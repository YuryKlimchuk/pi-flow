# web-ui-foundation Specification

## Purpose
Предоставляет браузерную основу локального интерфейса pi-flow для навигации к репозиториям и Issues без переноса бизнес-логики в web.

## Requirements

### Requirement: Модуль web
Модуль `web` SHALL быть отдельной границей Spring Modulith и SHALL содержать только транспорт и представление.

#### Scenario: Проверка границы
- **WHEN** выполняется проверка модульной архитектуры
- **THEN** пакет `com.hydroyura.agents.piflow.web` распознаётся как модуль без DDD-слоёв и бизнес-зависимостей

### Requirement: Технология интерфейса
Веб-интерфейс SHALL использовать Spring MVC-контроллеры и Thymeleaf-шаблоны, размещённые в `templates/`.

#### Scenario: Открытие приложения
- **WHEN** браузер запрашивает `GET /`
- **THEN** приложение возвращает HTML, отрендеренный Thymeleaf-шаблоном главной страницы

### Requirement: Навигационный layout
Главная страница SHALL предоставлять общий layout и ссылки на список репозиториев и доступный раздел Issues.

#### Scenario: Навигация
- **WHEN** пользователь открывает главную страницу
- **THEN** HTML содержит название приложения и навигационные ссылки, ведущие к страницам web

### Requirement: Страницы GitHub-данных
Web SHALL предоставлять отдельные GET-маршруты для списка репозиториев и Issues выбранного репозитория.

#### Scenario: Маршруты
- **WHEN** пользователь запрашивает страницу репозиториев или URL Issues с owner и repository
- **THEN** соответствующий контроллер возвращает страницу, а не JSON GitHub API

### Requirement: View-модели
Контроллеры web SHALL передавать в Thymeleaf только собственные view-модели и SHALL NOT передавать `github.api.RepositorySummary` или `IssueSummary` непосредственно.

#### Scenario: Изоляция представления
- **WHEN** контроллер строит модель страницы из результата github
- **THEN** модель содержит типы web-представления с полями страницы, а внутренние типы github отсутствуют
