# Spec Delta

## MODIFIED Requirements

### Requirement: Наблюдение анализа
Web SHALL периодически запрашивать публичное состояние запущенного workflow и показывать индикатор выполнения Analyst до получения терминального результата.

#### Scenario: Анализ выполняется
- **WHEN** публичное состояние workflow имеет статус `RUNNING` и этап `ANALYZING_REQUIREMENTS`
- **THEN** страница показывает индикатор «анализ выполняется» и продолжает обновление состояния без перехода в Temporal UI
#### Scenario: Ошибка анализа
- **WHEN** состояние workflow становится `FAILED`
- **THEN** страница показывает сообщение об ошибке и не показывает результат анализа как успешный

### Requirement: Отображение результата
Web SHALL отображать все результаты завершённых этапов в timeline и SHALL отображать актуальный результат ручного gate отдельно от исторических результатов. Результат завершения SHALL отображать имя ветки, commit id и URL опубликованной ветки, если они доступны.

#### Scenario: Анализ завершён
- **WHEN** публичное состояние содержит успешный результат анализа
- **THEN** HTML страницы содержит анализ в timeline без необходимости открывать workspace или Temporal UI
#### Scenario: Артефакт недоступен
- **WHEN** workflow завершил этап, но текст артефакта не может быть прочитан
- **THEN** страница показывает ошибку результата и не отображает кнопку продолжения для этого результата
#### Scenario: Следующий этап не реализован
- **WHEN** состояние имеет `currentStage=DESIGNING_SOLUTION` без результата Architect
- **THEN** страница показывает, что следующий этап выполняется или ожидает реализации, и не предлагает повторно продолжить прошлый результат
#### Scenario: Повторный анализ выполняется
- **WHEN** состояние имеет `currentStage=ANALYZING_REQUIREMENTS` и текущий результат отсутствует
- **THEN** страница показывает индикатор повторного анализа и не показывает устаревший текст как текущий
#### Scenario: Architect proposal завершён
- **WHEN** публичное состояние содержит валидный proposal Architect
- **THEN** HTML страницы содержит proposal отдельным timeline-блоком с его структурой
#### Scenario: История после Continue
- **WHEN** состояние имеет `currentStage=DESIGNING_SOLUTION` после Continue Analyst
- **THEN** страница продолжает показывать блок анализа и показывает состояние текущего проектирования
#### Scenario: Результат push
- **WHEN** workflow завершён успешно после публикации
- **THEN** HTML содержит branch name, commit id и абсолютный URL ветки в timeline или статусе
#### Scenario: Ошибка Git
- **WHEN** состояние workflow имеет `FAILED` из-за ошибки создания ветки, коммита или push
- **THEN** HTML показывает безопасное сообщение ошибки без stack trace и не показывает результат как успешный

### Requirement: Предложенное имя ветки
Web SHALL показывать branch name, предложенный Analyst, отдельно от текста анализа.

#### Scenario: Валидное предложение
- **WHEN** результат содержит валидное латинское Git-имя ветки
- **THEN** страница отображает это имя как предложение Analyst

### Requirement: Продолжение workflow
Web SHALL показывать «Продолжить» только для актуального успешного результата ручного gate и SHALL сохранять исторический блок после принятия команды продолжения. После утверждения Architect web SHALL показывать действие создания ветки, а после его успеха — действие push.

#### Scenario: Нажатие продолжения
- **WHEN** пользователь отправляет «Продолжить» для успешного результата
- **THEN** web вызывает публичную команду продолжения, сохраняет блок результата и показывает следующий этап
#### Scenario: Продолжение недоступно
- **WHEN** этап выполняется, завершился ошибкой или не содержит валидного результата
- **THEN** кнопка «Продолжить» отсутствует или отключена и команда не отправляется
#### Scenario: Повторное нажатие
- **WHEN** workflow уже перешёл на следующий этап
- **THEN** web не показывает кнопку «Продолжить» для исторического результата и не отправляет повторную команду
#### Scenario: Создание ветки
- **WHEN** состояние содержит утверждённые Analyst и Architect результаты и ветка ещё не создана
- **THEN** страница показывает кнопку «Создать ветку» и отправляет публичную команду создания ветки
#### Scenario: Push после создания ветки
- **WHEN** состояние содержит созданную итоговую ветку и локальный commit ещё не опубликован
- **THEN** страница показывает кнопку «Запушить изменения» и отправляет публичную команду push
#### Scenario: Действия недоступны после завершения
- **WHEN** состояние имеет `COMPLETED` или `FAILED`
- **THEN** страница не показывает активные кнопки создания ветки и push

### Requirement: Исправление анализа
Web SHALL предоставлять кнопку «Переделать» для актуального результата ручного gate и SHALL отправлять feedback отдельной публичной командой rework, не удаляя прошлые блоки.

#### Scenario: Ввод замечаний
- **WHEN** пользователь отправляет непустой feedback
- **THEN** web передаёт feedback для того же workflow и показывает новый выполняемый шаг, сохраняя предыдущий результат
#### Scenario: Пустые замечания
- **WHEN** пользователь отправляет пустой или состоящий из пробелов feedback
- **THEN** web не запускает rework и показывает ошибку валидации
