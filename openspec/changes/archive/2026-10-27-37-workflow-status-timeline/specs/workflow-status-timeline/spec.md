# Spec Delta

## Purpose
Предоставляет накопительную историю этапов workflow и результаты, чтобы статусная страница показывала проверяемый ход процесса, включая повторные итерации.

## ADDED Requirements

### Requirement: Накопительная история шагов
Публичное состояние Workflow SHALL содержать упорядоченную историю завершённых шагов, где каждый шаг включает stage, role, action, result или artifact, timestamp и runId.

#### Scenario: Анализ добавлен в timeline
- **WHEN** Analyst завершает анализ и workflow достигает ручного gate
- **THEN** состояние содержит отдельный шаг с `ANALYZING_REQUIREMENTS`, ролью Analyst, результатом анализа, временем и идентификатором запуска

### Requirement: Сохранение истории после перехода
Workflow SHALL сохранять завершённые шаги после Continue и SHALL добавлять новый шаг для каждого завершённого Rework, не заменяя ранее опубликованные результаты.

#### Scenario: Continue сохраняет результат
- **WHEN** пользователь продолжает workflow после анализа
- **THEN** timeline сохраняет блок анализа, а состояние текущего этапа меняется на `DESIGNING_SOLUTION`

#### Scenario: Rework сохраняет обе итерации
- **WHEN** пользователь отправляет feedback и повторный анализ завершается
- **THEN** timeline содержит исходный блок анализа и отдельный блок повторного анализа с новым runId

### Requirement: Timeline отображается на странице
Web SHALL отображать каждый элемент timeline отдельным блоком в порядке завершения и SHALL отображать результат каждого шага, доступный в публичном состоянии.

#### Scenario: Накопленные блоки
- **WHEN** состояние содержит подготовку, анализ и повторный анализ
- **THEN** страница статуса показывает три отдельные карточки в хронологическом порядке

### Requirement: Действия актуального gate
Web SHALL показывать «Продолжить» и «Переделать» только для актуального успешного результата ручного gate.

#### Scenario: Действия анализа
- **WHEN** текущий этап ожидает решения пользователя и содержит валидный результат
- **THEN** кнопки применяются к текущему шагу, а исторические карточки не получают повторных действий

#### Scenario: Выполнение этапа
- **WHEN** текущий этап выполняется или завершился ошибкой
- **THEN** кнопки ручного gate отсутствуют
