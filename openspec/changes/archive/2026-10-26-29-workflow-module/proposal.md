# Proposal

## Why

В проекте `pi-flow` пакет `workflow` пока является заглушкой, поэтому отсутствует единый владелец состояния и этапов бизнес-процесса разработки. Без этого нельзя безопасно запускать процесс сквозным сценарием и подключать Temporal, не смешивая доменную логику с SDK и существующими адаптерами `workspace`, `agent`, `github` и `interaction`.

## What Changes

- Добавить изолированную доменную модель Workflow с идентификатором, статусом, текущим этапом, историей завершённых этапов и проверяемыми допустимыми переходами.
- Добавить публичные контракты запуска workflow и получения его состояния.
- Добавить application-сценарий минимального запуска, который координирует подготовку workspace и запуск Temporal через порт прикладного слоя.
- Добавить Temporal workflow/activity-адаптер в infrastructure; домен и публичные контракты не будут зависеть от Temporal SDK.
- Использовать существующие публичные контракты `workspace`, `agent`, `github` и `interaction`; не дублировать Git, Pi, GitHub API или пользовательское взаимодействие в `workflow`.
- Добавить конфигурацию Temporal и локальный Dockerfile с Docker Compose для приложения, Temporal, PostgreSQL и Temporal UI.
- Добавить unit-, application-, Temporal-интеграционные и архитектурные тесты, включая проверку запрета утечки Temporal и инфраструктурных пакетов в домен/API.
- Добавить документацию по устройству модуля и локальному запуску.

## Capabilities

### New Capabilities

- `workflow-lifecycle`: доменная модель workflow, статусы, этапы, переходы, состояние и публичные операции запуска/просмотра.
- `workflow-temporal`: прикладной порт исполнения workflow и Temporal-адаптер для минимального сквозного запуска.
- `workflow-runtime`: конфигурация и локальный запуск приложения вместе с Temporal, а также проверяемые эксплуатационные предпосылки.

### Modified Capabilities

- Нет.

## Impact

Затрагиваются `src/main/java/.../workflow`, публичные API-контракты и тесты модулей, `pom.xml`, `src/main/resources/application.yaml`, Dockerfile, Docker Compose и документация. Потребуется зависимость Temporal SDK. Направление зависимостей сохраняется: `workflow` может использовать только публичные контракты `workspace`, `agent`, `interaction`, `github`; `web` остаётся адаптером и не получает прямого доступа к инфраструктуре workflow. Полная реализация всех этапов процесса, циклов ревью, пользовательских согласований и AI-логики не входит в изменение.
