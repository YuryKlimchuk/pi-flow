# Spec Delta

## ADDED Requirements

### Requirement: Публичный контракт операций GitHub
Публичный API модуля `github` SHALL предоставлять типизированные операции получения репозиториев, получения списка и деталей Issues, публикации подготовленной ветки и создания Pull Request.

#### Scenario: Workflow использует контракт
- **WHEN** `workflow` запрашивает операцию GitHub
- **THEN** вызов проходит через тип из `github.api`, а не через инфраструктурный класс.

### Requirement: Изолированные публичные модели
Модели `github.api` SHALL содержать только данные контракта и SHALL NOT зависеть от HTTP-клиента, HTTP DTO или инфраструктурных пакетов.

#### Scenario: Проверка модели
- **WHEN** компилятор анализирует зависимости публичных моделей
- **THEN** в них отсутствуют импорты `github.infrastructure` и классов HTTP-клиента.

### Requirement: Application-оркестрация
Application-реализации SHALL делегировать операции внутреннему порту GitHub API и SHALL преобразовывать его результаты и ошибки в публичные типы.

#### Scenario: Делегирование
- **WHEN** вызывается публичный порт с валидными параметрами
- **THEN** ровно соответствующая операция внутреннего порта вызывается и её результат возвращается потребителю.

### Requirement: Границы Modulith
Модуль `github` SHALL быть отдельной границей Spring Modulith, а `workflow` SHALL зависеть от `github` только через его публичный API.

#### Scenario: Архитектурная проверка
- **WHEN** выполняется `ApplicationModules.of(PiFlowApplication.class).verify()`
- **THEN** проверка завершается успешно и прямой импорт `github.infrastructure` из `workflow` отсутствует.

### Requirement: Изоляция локального Git
Модуль `github` SHALL NOT выполнять локальные Git-команды, читать локальную файловую систему или содержать переходы workflow.

#### Scenario: Передача подготовленной ветки
- **WHEN** публичному порту передаётся имя подготовленной ветки
- **THEN** модуль принимает только удалённую GitHub-операцию, оставляя подготовку и локальный push модулю `workspace`.
