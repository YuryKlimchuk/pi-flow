# workspace-module-contract Specification

## Purpose
Определяет изолированный публичный контракт workspace для подготовки локального рабочего пространства Workflow и безопасного получения результата без утечки Git-инфраструктуры.

## Requirements

### Requirement: Каркас модуля
Модуль `workspace` SHALL быть листовым Spring Modulith-модулем с публичным API и внутренними слоями application, domain и infrastructure.

#### Scenario: Проверка границы
- **WHEN** выполняется проверка модульной структуры
- **THEN** `workspace` не имеет зависимостей от `workflow`, `agent`, `interaction`, `github` или `web`, а внешние типы доступны только через `workspace.api`

### Requirement: Порт подготовки
`workspace.api` SHALL предоставлять операцию подготовки рабочего пространства по входной команде.

#### Scenario: Запрос подготовки
- **WHEN** вызывающая сторона передаёт валидную команду подготовки
- **THEN** workspace принимает её через публичный порт без требования знать внутренние классы

### Requirement: Входная модель
Команда подготовки SHALL содержать идентификатор Workflow, адрес репозитория, целевую ветку и параметры размещения.

#### Scenario: Полный запрос
- **WHEN** команда содержит все четыре значения
- **THEN** каждое значение доступно обработчику подготовки как часть типизированной модели

### Requirement: Результат пространства
Результат подготовки SHALL содержать путь к рабочей директории, адрес репозитория и фактически выбранную ветку.

#### Scenario: Успешная подготовка
- **WHEN** рабочая директория подготовлена
- **THEN** вызывающая сторона получает путь, сведения о репозитории и ветке через `workspace.api`

### Requirement: Модель ошибок
Workspace SHALL возвращать типизированные ошибки валидации, доступа к репозиторию, файловой системы и Git без обязательного экспорта исключений инфраструктурного адаптера.

#### Scenario: Некорректный запрос
- **WHEN** адрес репозитория или идентификатор Workflow невалиден
- **THEN** публичный порт возвращает ошибку валидации с причиной, пригодной для обработки вызывающей стороной

### Requirement: Порт локального Git
Внутренний domain-порт локального Git SHALL отделять application-логику от адаптера, а публичные модели SHALL NOT зависеть от Git API. Публичный workspace-контракт SHALL принимать команды создания итоговой ветки и коммита артефактов.

#### Scenario: Архитектурная проверка
- **WHEN** анализируются зависимости `workspace.api`
- **THEN** они не содержат типов JGit, CLI, `Process` или `workspace.infrastructure`

#### Scenario: Вызов через публичный API
- **WHEN** workflow передаёт команду создания ветки или коммита
- **THEN** workspace принимает её через `workspace.api` и возвращает сериализуемый результат либо типизированную ошибку
