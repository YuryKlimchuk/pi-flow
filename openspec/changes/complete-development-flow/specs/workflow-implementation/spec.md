# Spec Delta

## Purpose

Выполняет утверждённое проектное решение в рабочем репозитории и предоставляет проверяемый результат сборки и тестов перед ревью.

## ADDED Requirements

### Requirement: Реализация решения Developer
Temporal execution SHALL запускать роль `DEVELOPER` после утверждения Architect и SHALL передавать ей рабочую директорию, Issue-контекст и утверждённый design artifact.

#### Scenario: Успешная реализация
- **WHEN** Architect gate утверждён
- **THEN** execution запускает `DEVELOPER` на этапе `IMPLEMENTING`, а изменения появляются в рабочей директории

### Requirement: Проверка реализации
Этап `IMPLEMENTING` SHALL считать реализацию успешной только после успешного завершения сборки и тестов проекта.

#### Scenario: Сборка и тесты пройдены
- **WHEN** Developer завершил изменения и команды сборки и тестов возвращают код 0
- **THEN** результат реализации помечается успешным и execution переходит к `REVIEWING`

#### Scenario: Сборка или тесты не пройдены
- **WHEN** сборка или тесты возвращают ненулевой код либо Developer завершается ошибкой
- **THEN** execution остаётся на `IMPLEMENTING`, сохраняет диагностический результат и предоставляет повторную итерацию либо переводит workflow в `FAILED` после исчерпания лимита

### Requirement: Rework реализации
Workflow SHALL принимать feedback для повторной реализации не более трёх раз для одного цикла реализации.

#### Scenario: Повторная реализация с feedback
- **WHEN** пользователь отправляет непустой feedback на результате реализации или ревью при счётчике итераций меньше 3
- **THEN** execution запускает новый `DEVELOPER` run на той же рабочей ветке и сохраняет предыдущий результат в timeline

#### Scenario: Превышение лимита
- **WHEN** запрошена четвёртая итерация rework одного цикла
- **THEN** workflow переводится в `FAILED`, новый запуск Developer не выполняется, а workspace lock освобождается
