# agent-module-contract Specification

## Purpose
Определяет публичный контракт модуля `agent`, который позволяет workflow запускать техническую задачу Pi и получать результат, не зная деталей процесса или транспорта.

## Requirements

### Requirement: Публичный порт запуска
Публичный API `agent.api` SHALL предоставлять операцию запуска задачи агента и получения технического результата через типизированные модели.

#### Scenario: Workflow запускает задачу
- **WHEN** `workflow` передаёт валидную команду запуска через `agent.api`
- **THEN** модуль принимает команду и возвращает результат по публичному контракту без обращения к инфраструктурному типу.

### Requirement: Входная модель запуска
Команда запуска SHALL содержать роль или профиль, инструкцию, входные данные и параметры запуска, необходимые для одного изолированного запуска.

#### Scenario: Переданы все входные данные
- **WHEN** команда содержит `role`, `instruction`, `inputData` и параметры
- **THEN** каждый элемент доступен application-слою без чтения его из workflow-состояния.

### Requirement: Выходная модель результата
Результат SHALL содержать идентификатор запуска, технический статус, текстовый ответ, exit code при наличии и доступные технические метаданные.

#### Scenario: Успешный результат
- **WHEN** Pi завершает задачу успешно и возвращает текст
- **THEN** вызывающая сторона получает статус успеха, текст и exit code через `agent.api`.

### Requirement: Типизированные ошибки
Модуль SHALL различать ошибки подготовки запуска, запуска процесса, выполнения Pi и обработки результата.

#### Scenario: Ошибка запуска
- **WHEN** внешний процесс не может быть создан
- **THEN** публичный порт возвращает ошибку запуска, не раскрывая `IOException` как обязательную часть контракта.

### Requirement: Изоляция деталей Pi
Публичные типы `agent.api` SHALL NOT зависеть от `Process`, shell-команд, HTTP/RPC клиентов или пакетов `agent.infrastructure`.

#### Scenario: Архитектурная проверка
- **WHEN** проверяются зависимости `workflow` и `agent.api`
- **THEN** `workflow` импортирует только публичный API, а детали Pi остаются внутри `agent`.

### Requirement: Листовая граница модуля
Модуль `agent` SHALL NOT содержать операции workflow, локальный Git или прямые вызовы GitHub API.

#### Scenario: Проверка ответственности
- **WHEN** выполняется архитектурная проверка модулей
- **THEN** у `agent` отсутствует зависимость от `workspace`, `github` и `web`.

### Requirement: Контракт запуска Analyst из workflow
Публичный API `agent` SHALL принимать сериализуемый контекст Analyst через существующую модель команды и возвращать технический результат, достаточный для проверки успешного завершения и сохранённого артефакта.

#### Scenario: Workflow вызывает Analyst
- **WHEN** activity передаёт роль `ANALYST`, инструкцию, Issue-контекст, путь workspace и параметры результата
- **THEN** `agent.api` возвращает `AgentRunResult` без раскрытия инфраструктурной реализации процесса

### Requirement: Изоляция Temporal
Модуль `agent` SHALL NOT импортировать Temporal API или зависеть от реализации Temporal activity.

#### Scenario: Архитектурная проверка
- **WHEN** проверяются зависимости agent API и реализации agent
- **THEN** Temporal-типы отсутствуют в модуле `agent`
