# workflow-list Specification

## Purpose
Позволяет пользователю найти ранее запущенный workflow и вернуться к его накопительному статусу без хранения ссылки на страницу.

## Requirements

### Requirement: Список запущенных workflow
Публичный API workflow SHALL возвращать список сохранённых workflow с идентификатором, репозиторием, номером issue, статусом и текущим этапом.

#### Scenario: Получение списка
- **WHEN** вызывающая сторона запрашивает список workflow
- **THEN** каждый сохранённый workflow представлен указанными полями

### Requirement: Навигация к статусу
Web SHALL предоставлять страницу списка workflow, а каждая строка SHALL содержать ссылку на `/workflows/track` с соответствующим workflow id.

#### Scenario: Возврат к workflow
- **WHEN** пользователь открывает список и выбирает workflow
- **THEN** браузер переходит на `/workflows/track?workflowId=<id>`

### Requirement: Ограничение хранения списка
In-memory реализация SHALL сохранять список только в памяти процесса и SHALL возвращать пустой список после перезапуска приложения.

#### Scenario: Перезапуск
- **WHEN** приложение перезапущено без внешнего хранилища
- **THEN** ранее сохранённые workflow отсутствуют в списке
