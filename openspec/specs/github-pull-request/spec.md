# github-pull-request Specification

## Purpose
Предоставляет workflow удалённую публикацию подготовленной ветки и безопасное создание Pull Request без дубликатов при повторном выполнении.

## Requirements

### Requirement: Публикация подготовленной ветки
Операция SHALL публиковать переданную подготовленную ветку в GitHub через публичный контракт публикации и SHALL возвращать ref и URL удалённой ветки без локальных Git-операций; операция SHALL NOT создавать Pull Request.

#### Scenario: Ветка опубликована
- **WHEN** переданы repository и имя локально подготовленной ветки
- **THEN** результат содержит ref и URL удалённой ветки, а локальный Git CLI и файловая система не используются

#### Scenario: PR не создаётся
- **WHEN** workflow выполняет push после локального коммита
- **THEN** вызывается только публикация ветки, а операция создания Pull Request не вызывается

### Requirement: Валидация команды PR
Команда создания PR SHALL отклонять отсутствующие или пустые repository, base, head и title до HTTP-вызова.

#### Scenario: Невалидная команда
- **WHEN** title или head пусты
- **THEN** возвращается ошибка валидации и GitHub не получает запрос.

### Requirement: Создание Pull Request
Операция SHALL принимать repository, base, head, title и description и SHALL возвращать положительный номер и абсолютный URL созданного PR.

#### Scenario: PR создан
- **WHEN** head опубликован и GitHub принимает POST
- **THEN** возвращаются номер и абсолютный URL нового PR.

### Requirement: Идемпотентность открытого PR
Операция SHALL искать открытый PR по repository, head и base до POST и SHALL возвращать найденный PR без создания дубликата.

#### Scenario: Открытый PR уже существует
- **WHEN** поиск возвращает открытый PR с теми же head и base
- **THEN** возвращаются его номер и URL, а POST создания не выполняется.

### Requirement: Гонка создания PR
При 409 или 422 во время создания операция SHALL повторно искать открытый PR и SHALL возвращать его, если он появился.

#### Scenario: Конкурирующее создание
- **WHEN** POST возвращает 409 или 422, а повторный поиск находит открытый PR
- **THEN** результатом становится найденный PR, а не ошибка дубликата.

### Requirement: Закрытый PR не является открытым
Операция SHALL игнорировать закрытый PR при проверке идемпотентности и SHALL создать новый PR либо вернуть явную policy/error-ошибку.

#### Scenario: Только закрытый PR
- **WHEN** поиск возвращает только закрытый PR
- **THEN** закрытый PR не возвращается как результат открытой операции.
