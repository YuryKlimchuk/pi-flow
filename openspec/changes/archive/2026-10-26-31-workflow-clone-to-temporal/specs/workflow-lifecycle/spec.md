# Spec Delta

## MODIFIED Requirements

### Requirement: Создание Workflow
Публичный контракт `workflow` SHALL создавать Workflow с уникальным идентификатором, контекстом выбранного репозитория и Issue, статусом `CREATED` и этапом `ANALYZING_REQUIREMENTS`.

#### Scenario: Валидная команда запуска
- **WHEN** команда содержит идентификатор репозитория, номер задачи и непустой идентификатор workflow
- **THEN** результат содержит тот же идентификатор и состояние `CREATED` на этапе `ANALYZING_REQUIREMENTS`

#### Scenario: Валидная команда запуска по Issue
- **WHEN** команда содержит owner, repository, положительный issue number и непустой идентификатор workflow
- **THEN** результат содержит контекст репозитория, номер Issue, тот же идентификатор и состояние `CREATED` на этапе `ANALYZING_REQUIREMENTS`

#### Scenario: Невалидная команда
- **WHEN** отсутствует owner или repository либо номер задачи не положителен
- **THEN** команда отклоняется типизированной ошибкой валидации и Workflow не создаётся

### Requirement: Границы ответственности Workflow
Workflow SHALL координировать создание состояния и запуск длительного исполнения через публичные контракты, SHALL NOT выполнять локальные Git-операции самостоятельно и SHALL NOT вызывать `agent.run` в минимальном сценарии до клонирования репозитория.

#### Scenario: Координация зависимостей
- **WHEN** минимальный запуск требует подготовки workspace и технического запуска агента
- **THEN** workflow вызывает `workspace.api` и `agent.api`, а не JGit, `Process`, GitHub HTTP-клиент или Pi напрямую

#### Scenario: Минимальная координация
- **WHEN** валидная команда запуска передана
- **THEN** workflow создаёт состояние и инициирует execution, не вызывая агент и не импортируя Git/JGit реализацию
