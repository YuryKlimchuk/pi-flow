# Design

## Context

См. `proposal.md` — Why. Модуль `web` уже существует как пустой адаптер (из change `3-modular-architecture-skeleton`). Точка входа — `PiFlowApplication` (сейчас вызывает `System.exit`, что не подходит для веб-сервера).

## Goals / Non-Goals

**Goals:**
- Подключить web-слой и Thymeleaf.
- Добавить контроллер приветствия в модуль `web`.
- Обеспечить, что приложение остаётся запущенным как веб-сервер.

**Non-Goals:**
- Не добавляется бизнес-логика workflow.
- Не создаются API для запуска процессов (это позже).

## Decisions

### D1: Spring MVC + Thymeleaf

Используются `spring-boot-starter-web` и `spring-boot-starter-thymeleaf`.

- **Почему**: стандарт для server-rendered приветственной страницы.
- **Альтернатива**: REST-контроллер без шаблонов — отклонено, так как нужна HTML-страница.

### D2: Контроллер размещается в модуле `web`

Контроллер `WelcomeController` лежит в `com.hydroyura.agents.piflow.web`, по `GET /` возвращает имя шаблона `index`.

- **Почему**: web — интерфейсный адаптер, не содержит бизнес-логики.
- **Альтернатива**: контроллер в корневом пакете — отклонено (нарушает границы модулей).

### D3: Точка входа без `System.exit`

`main` становится `public static void main` и не вызывает `System.exit`, оставляя сервер запущенным.

- **Почему**: иначе контекст закрывается сразу после старта.
- **Альтернатива**: оставить `System.exit` — отклонено.

## Risks / Trade-offs

### R1: Spring Shell в зависимостях

[Risk] Присутствует `spring-shell-starter`; его поведение при веб-запуске может конфликтовать. → Mitigation: при необходимости ограничить/отключить shell-автозапуск позже; сейчас оставляем как есть.
