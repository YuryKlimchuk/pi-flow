# agent-process Specification

## Purpose
Фиксирует выполнение задачи Pi через CLI subprocess, безопасную передачу входа, сбор обоих потоков, exit code и освобождение ресурсов.

## Requirements

### Requirement: CLI subprocess
Модуль SHALL запускать Pi как отдельный CLI-процесс через механизм, эквивалентный `ProcessBuilder`, и SHALL NOT требовать RPC для основного сценария.

#### Scenario: Запуск Pi
- **WHEN** подготовлена валидная команда
- **THEN** создаётся отдельный Pi-процесс с указанной рабочей директорией.

### Requirement: Передача задачи
Адаптер SHALL передавать feedback Analyst как экранированные данные инструкции или входного сообщения без shell-интерпретации и без добавления feedback в команду как исполняемый код.

#### Scenario: Входная задача
- **WHEN** инструкция содержит многострочный текст
- **THEN** Pi получает тот же текст через `--append-system-prompt` или первый промпт без выполнения его shell-интерпретатором

#### Scenario: Подтверждённый CLI-контракт
- **WHEN** запускается Pi v1.4.0 в неинтерактивном режиме
- **THEN** runner использует `--print` и передаёт роль/инструкцию через `--append-system-prompt` и первый промпт, а контекст-файлы — через `@path`

#### Scenario: Ненулевой код завершения
- **WHEN** Pi завершает run с ошибкой, abort или обрезкой по лимиту в print-режиме
- **THEN** runner возвращает ненулевой exit code и не помечает запуск успешным

#### Scenario: Многострочный feedback
- **WHEN** feedback содержит переносы строк, кавычки или символы shell
- **THEN** Pi получает исходный текст как данные и не выполняет его как shell-команду

### Requirement: Сбор stdout и stderr
Модуль SHALL читать stdout и stderr независимо до завершения процесса.

#### Scenario: Большой вывод
- **WHEN** Pi пишет объём stdout и stderr, превышающий буфер ОС
- **THEN** процесс завершается, а оба потока доступны в техническом результате без взаимной блокировки.

### Requirement: Exit code
Результат запуска SHALL содержать exit code после завершения Pi.

#### Scenario: Нулевой exit code
- **WHEN** Pi завершается с кодом `0`
- **THEN** результат содержит `0` и собранный stdout.

### Requirement: Освобождение ресурсов
Адаптер SHALL закрывать потоки ввода-вывода и освобождать процессные ресурсы после завершения или ошибки.

#### Scenario: Ошибка во время чтения
- **WHEN** чтение потока завершается исключением
- **THEN** reader-ы закрываются и дочерний процесс не остаётся активным без владельца.

### Requirement: RPC отложен
Модуль SHALL NOT создавать второй RPC-механизм в рамках этого change.

#### Scenario: Архитектурная проверка транспорта
- **WHEN** проверяется набор адаптеров agent
- **THEN** присутствует CLI subprocess адаптер, а обязательного RPC-адаптера нет.
