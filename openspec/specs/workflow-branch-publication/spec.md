# workflow-branch-publication Specification

## Purpose
Предоставляет пользователю завершающий участок workflow: создание ветки с предложенным именем, фиксацию артефактов и публикацию ветки в GitHub с наблюдаемым результатом.

## Requirements

### Requirement: Создание итоговой ветки
Публичный workflow SHALL создавать и переключать локальную ветку с именем `branchName` из последнего успешного результата Analyst.

#### Scenario: Создание ветки после Architect gate
- **WHEN** workflow имеет валидные результаты Analyst и Architect, а пользователь нажимает «Создать ветку»
- **THEN** создаётся ветка с именем из `branchName`, а не `pi-flow/<workflowId>`, и состояние содержит это имя

### Requirement: Доступность создания ветки
Workflow SHALL принимать создание итоговой ветки только после успешного Architect gate и SHALL отклонять повторное создание после успешного создания.

#### Scenario: Раннее действие
- **WHEN** пользователь нажимает «Создать ветку» до успешного Architect proposal
- **THEN** операция отклоняется типизированной ошибкой, состояние не изменяется, и push недоступен

### Requirement: Коммит артефактов
Операция push SHALL создавать локальный коммит ровно с `.pi-flow/analysis/analyst.md` и `.pi-flow/design/architect.md` и SHALL возвращать commit id.

#### Scenario: Успешный коммит
- **WHEN** итоговая ветка создана и оба артефакта доступны
- **THEN** коммит содержит оба указанных пути, а timeline и состояние содержат непустой commit id

### Requirement: Публикация ветки
Операция push SHALL публиковать созданную ветку через публичную операцию GitHub и SHALL сохранять URL опубликованной ветки.

#### Scenario: Успешный push
- **WHEN** локальный коммит завершён и GitHub принимает публикацию
- **THEN** workflow становится `COMPLETED`, timeline содержит branch name, commit id и URL, а повторный push не создаёт новый результат

### Requirement: Ошибка завершения
Ошибки создания ветки, коммита или публикации SHALL переводить workflow в `FAILED` и SHALL сохранять только безопасное сообщение без stack trace.

#### Scenario: Ошибка публикации
- **WHEN** GitHub отклоняет публикацию после успешного локального коммита
- **THEN** состояние имеет статус `FAILED`, содержит сообщение причины без stack trace, и не объявляет push успешным

### Requirement: In-memory ограничение
Workflow SHALL хранить результаты создания ветки и push только в текущем in-memory хранилище.

#### Scenario: Перезапуск приложения
- **WHEN** приложение перезапущено после завершения push
- **THEN** ранее сохраненное состояние workflow недоступно через новый экземпляр хранилища
