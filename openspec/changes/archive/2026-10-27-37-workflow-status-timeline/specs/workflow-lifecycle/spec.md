# Spec Delta

## MODIFIED Requirements

### Requirement: Модель состояния Workflow
Workflow SHALL предоставлять текущий этап, актуальный результат ручного gate и неизменяемую историю всех завершённых шагов с их результатами; после Continue старый результат SHALL оставаться доступным только через историю.

#### Scenario: Чтение состояния
- **WHEN** вызывающая сторона запрашивает состояние созданного Workflow
- **THEN** получает идентификатор, статус, текущий этап, пустую историю шагов и контрольные точки через публичный контракт

#### Scenario: Чтение результата
- **WHEN** вызывающая сторона запрашивает состояние workflow после успешного анализа
- **THEN** получает текущий результат анализа и отдельную запись анализа в истории шагов

#### Scenario: Состояние следующего этапа
- **WHEN** Workflow успешно продолжен после анализа
- **THEN** состояние содержит `currentStage=DESIGNING_SOLUTION`, а результат анализа остаётся доступным в истории

#### Scenario: Состояние rework
- **WHEN** rework принят до завершения нового анализа
- **THEN** состояние содержит текущий этап анализа, не публикует старый результат как актуальный и сохраняет старый результат в истории

### Requirement: Допустимые переходы
Домен Workflow SHALL разрешать переход с ручного gate на следующий этап ровно один раз и SHALL сохранять результат каждой завершённой итерации этапа перед переходом или rework.

#### Scenario: Переход после Analyst
- **WHEN** Workflow в `WAITING_FOR_USER` после успешного анализа и пользователь принимает «Продолжить»
- **THEN** статус становится `RUNNING`, текущим этапом становится `DESIGNING_SOLUTION`, а результат анализа добавляется в историю

#### Scenario: Переход после Architect
- **WHEN** Workflow в `WAITING_FOR_USER` после успешного Architect proposal и пользователь принимает «Продолжить»
- **THEN** статус становится `RUNNING`, текущим этапом становится `IMPLEMENTING`, а proposal остаётся в истории

#### Scenario: Запрещённый переход
- **WHEN** вызывающая сторона запрашивает переход, не разрешённый из текущего состояния
- **THEN** состояние Workflow не изменяется и возвращается ошибка недопустимого перехода

#### Scenario: Повторное продолжение
- **WHEN** пользователь повторно отправляет команду продолжения вне ручного gate
- **THEN** домен отклоняет команду и не добавляет новый этап в историю

#### Scenario: Rework текущего этапа
- **WHEN** Workflow имеет результат текущего этапа и получает непустой feedback
- **THEN** текущий результат сохраняется в истории, публикуемый результат очищается, а статус становится `RUNNING`
