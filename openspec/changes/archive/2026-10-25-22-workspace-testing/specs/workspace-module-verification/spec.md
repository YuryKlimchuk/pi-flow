# Spec Delta

## Purpose

Определяет обязательное автоматизированное подтверждение поведения workspace, его ошибок, конкурентного доступа и границы Spring Modulith перед передачей модуля в реализацию workflow.

## ADDED Requirements

### Requirement: Проверка входов и директории
Тестовый набор SHALL проверять валидацию параметров и детерминированный выбор директории.

#### Scenario: Негативные параметры
- **WHEN** тест передаёт невалидный URL, ветку или путь
- **THEN** тест подтверждает типизированную ошибку без Git-операции

### Requirement: Проверка clone/update
Тестовый набор SHALL проверять clone отсутствующей копии, update чистой копии и отказ на dirty tree.

#### Scenario: Локальные изменения
- **WHEN** update запускается на копии с незакоммиченным файлом
- **THEN** тест подтверждает ошибку и сохранение файла

### Requirement: Проверка веток
Тестовый набор SHALL проверять создание, повторное использование и переключение `pi-flow/{workflowId}`.

#### Scenario: Повторный запрос
- **WHEN** рабочая ветка уже существует
- **THEN** тест подтверждает отсутствие дубликата и checkout существующей ветки

### Requirement: Проверка ошибок
Тестовый набор SHALL проверять ошибки Git, файловой системы, доступа и повреждённой копии с сохранением диагностируемого состояния.

#### Scenario: Повреждённая копия
- **WHEN** путь содержит неполную рабочую копию
- **THEN** тест подтверждает ошибку и отсутствие автоматического удаления

### Requirement: Проверка конкуренции
Тестовый набор SHALL проверять, что для одного repository key одновременно активен максимум один lease.

#### Scenario: Два владельца
- **WHEN** два потока одновременно получают один lock
- **THEN** ровно один получает lease, а второй получает busy

### Requirement: Проверка освобождения
Тестовый набор SHALL проверять освобождение lock после успеха и после исключения.

#### Scenario: Ошибка и повтор
- **WHEN** владелец завершает операцию исключением, а затем приходит новый запрос
- **THEN** новый запрос получает lock

### Requirement: Проверка границы
Архитектурный тест SHALL подтверждать отсутствие бизнес-зависимостей workspace и доступность внутренних слоёв только внутри модуля.

#### Scenario: Modulith verification
- **WHEN** запускается проверка `ApplicationModules.verify()`
- **THEN** не обнаруживаются циклы, зависимости на бизнес-модули или обход `workspace.api`
