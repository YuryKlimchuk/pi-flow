# Spec Delta

## MODIFIED Requirements

### Requirement: Продолжение workflow
Web SHALL показывать «Продолжить» только для актуального успешного результата Analyst и SHALL скрывать её после принятия команды продолжения.

#### Scenario: Нажатие продолжения
- **WHEN** пользователь отправляет «Продолжить» для успешного анализа
- **THEN** web вызывает публичную команду продолжения и показывает этап `DESIGNING_SOLUTION` без карточки текущего результата Analyst

#### Scenario: Продолжение недоступно
- **WHEN** анализ выполняется, завершился ошибкой или не содержит валидного branch name
- **THEN** кнопка «Продолжить» отсутствует или отключена и команда продолжения не отправляется

#### Scenario: Повторное нажатие
- **WHEN** Workflow уже находится на `DESIGNING_SOLUTION`
- **THEN** web не показывает кнопку «Продолжить» и не отправляет повторную команду

### Requirement: Отображение результата
Web SHALL отображать полный текст только актуального результата анализа и SHALL прекращать отображение старого результата после Continue или принятого rework.

#### Scenario: Анализ завершён
- **WHEN** публичное состояние содержит успешный результат анализа и доступный текст артефакта
- **THEN** HTML страницы содержит текст артефакта без необходимости открывать workspace или Temporal UI

#### Scenario: Артефакт недоступен
- **WHEN** workflow завершил Analyst, но текст артефакта не может быть прочитан
- **THEN** страница показывает ошибку результата и не отображает кнопку продолжения

#### Scenario: Следующий этап не реализован
- **WHEN** состояние имеет `currentStage=DESIGNING_SOLUTION` без execution Architect
- **THEN** страница показывает, что следующий этап ожидает реализации, и не предлагает повторно продолжить workflow

#### Scenario: Повторный анализ выполняется
- **WHEN** состояние имеет `currentStage=ANALYZING_REQUIREMENTS` и `analysisText=null`
- **THEN** страница показывает индикатор повторного анализа и не показывает устаревший текст

## ADDED Requirements

### Requirement: Исправление анализа
Web SHALL предоставлять кнопку «Исправить» для актуального результата Analyst и SHALL отправлять введённый feedback отдельной публичной командой rework.

#### Scenario: Ввод замечаний
- **WHEN** пользователь нажимает «Исправить» и отправляет непустой текст замечаний
- **THEN** web передаёт feedback для того же workflow и показывает повторный анализ на этапе `ANALYZING_REQUIREMENTS`

#### Scenario: Пустые замечания
- **WHEN** пользователь отправляет пустой или состоящий из пробелов feedback
- **THEN** web не запускает rework и показывает ошибку валидации
