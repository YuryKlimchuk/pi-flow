# agent-roles Specification

## Purpose
Определяет роль как параметр запуска Pi, передачу профильных инструкций и контекста, а также изоляцию входов и результатов независимых запусков.

## Requirements

### Requirement: Модель роли
Команда запуска SHALL принимать роль или профиль с устойчивым идентификатором, а Analyst, Architect, Developer и Reviewer SHALL представляться параметрами, а не отдельными Java-сервисами.

#### Scenario: Запуск Reviewer
- **WHEN** вызывающая сторона указывает роль `Reviewer`
- **THEN** роль попадает в metadata запуска и используется для выбора инструкции.

### Requirement: Профильная инструкция
Модуль SHALL разрешать профильную инструкцию через поддерживаемый источник профилей, SHALL передавать её выбранному Pi-запуску и SHALL требовать от профиля Architect фиксированный proposal-формат.

#### Scenario: Профиль Architect
- **WHEN** задан профиль `Architect` с инструкцией
- **THEN** только этот запуск получает соответствующую профильную инструкцию, требующую разделы `Why`, `What Changes`, `Capabilities`, `Impact` и `Non-goals`

#### Scenario: Профиль Analyst
- **WHEN** задан профиль `Analyst` с инструкцией
- **THEN** запуск получает инструкцию Analyst без требований Architect proposal

### Requirement: Контекст задачи
Модуль SHALL передавать конкретному запуску instruction, input data, context и рабочую директорию из его команды.

#### Scenario: Контекст repository
- **WHEN** запуск получает контекст репозитория и задачу
- **THEN** Pi получает оба значения, а результат содержит идентификатор этого запуска.

### Requirement: Изоляция запусков
Каждый запуск SHALL иметь уникальный идентификатор и SHALL NOT читать или изменять входы, инструкции и результаты другого активного запуска.

#### Scenario: Параллельные роли
- **WHEN** Analyst и Reviewer запускаются одновременно с разными контекстами
- **THEN** каждый процесс получает только свои данные и возвращает свой run id.

### Requirement: Возврат через публичный контракт
Результат роли SHALL возвращаться через `agent.api` и SHALL содержать технический статус и role/run metadata.

#### Scenario: Получение результата
- **WHEN** Pi завершает запуск роли
- **THEN** workflow получает result через публичный порт без доступа к infrastructure.

### Requirement: Отсутствие workflow-оркестрации
Модуль `agent` SHALL NOT определять порядок ролей, переходы этапов или approval gates.

#### Scenario: Вызов одной роли
- **WHEN** workflow запрашивает запуск роли
- **THEN** agent выполняет только этот запуск и не инициирует следующую роль.

### Requirement: Proposal Architect
Результат успешного запуска роли Architect SHALL быть proposal-артефактом с обязательными разделами `Why`, `What Changes`, `Capabilities`, `Impact` и `Non-goals`.

#### Scenario: Завершение Architect
- **WHEN** Architect завершает запуск с кодом успеха
- **THEN** его артефакт содержит все обязательные proposal-разделы и непустое содержимое каждого раздела
