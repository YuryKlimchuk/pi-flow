# Proposal

## Why

После создания UI приложение должно безопасно использовать локально заданный PAT и объяснять пользователю отсутствие или недействительность конфигурации. Это продолжает change 23 и использует уже реализованную конфигурацию `github.api.token`.

## What Changes

- Зафиксировать `GITHUB_PI_FLOW_TOKEN` как источник PAT через конфигурацию `github.api.token`.
- Проверять конфигурацию при вызове GitHub-функций через существующий контракт.
- Отображать состояние подключения и понятные ошибки без раскрытия секрета.
- Не читать PAT в web самостоятельно и не дублировать GitHub-клиент.

## Capabilities

### New Capabilities
- `web-github-configuration`: безопасная конфигурация PAT и состояние подключения в UI.

### Modified Capabilities
- Нет.

## Impact

Затрагиваются обработка ошибок и представление в `web`; настройка `application.yaml` и `github.api` остаются источником истины. Change зависит от 23 и подготавливает 25–28.
